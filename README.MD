CAN Telemetry Gateway & Simulator

🛰️ Обзор проекта
Данный проект представляет собой программный шлюз для сбора и трансляции телеметрии от оборудования по протоколу CAN.
Проект спроектирован по принципу HIL (Hardware-in-the-Loop) тестирования:
Emulator: Имитирует бортовой узел спутника, генерируя поток данных телеметрии (напряжение, ток) в шину CAN.
Gateway: Выступает в роли шлюза, агрегирует данные из шины и предоставляет к ним доступ через современные интерфейсы: REST API и индустриальный стандарт OPC UA.

🛠 Технологический стек
Язык: Python 3.9+ (Asyncio)
Шина данных: SocketCAN (Virtual CAN)
API: FastAPI (Uvicorn)
Industrial: OPC UA (AsyncUA)
Infrastructure: Docker, Docker Compose
🚀 Быстрый запуск (Quick Start)

1. Подготовка хост-системы (Linux)
Для работы проекта необходимо поднять виртуальный интерфейс CAN в ядре Linux:
bash
sudo modprobe vcan
sudo ip link add dev vcan0 type vcan
sudo ip link set up vcan0
Используйте код с осторожностью.

2. Развертывание в Docker
Проект полностью контейнеризирован. Для запуска всей инфраструктуры (Шлюз + Эмулятор) выполните:
bash
docker compose up --build

📊 Доступ к данным
После запуска система доступна по следующим адресам:
Интерфейс	Адрес / Протокол	Описание
REST API	http://localhost:8000/telemetry	Текущий снимок данных в JSON
OPC UA	opc.tcp://localhost:4840	Стриминг данных для промышленных систем
CAN Bus	vcan0 (SocketCAN)	Для доступа к сырым кадрам шины

🏗 Архитектура решения
Асинхронность: Использование asyncio позволяет параллельно обрабатывать высокоскоростную CAN-шину и обслуживать внешние сетевые запросы без блокировок.
Контейнеризация: Режим network_mode: host обеспечивает прямой доступ к сетевому стеку SocketCAN изнутри Docker-контейнеров.
Масштабируемость: Архитектура шлюза позволяет легко добавлять новые ID сообщений CAN или подключать дополнительные протоколы (Modbus, Ethernet UDP/TCP).

🧪 Отладка и мониторинг
Для мониторинга «сырого» трафика в шине необходимо использовать инструменты can-utils:
bash
candump vcan0
Вы увидите пакеты телеметрии:
0x101 — Напряжение бортовой сети (float32)
0x102 — Ток потребления (float32)

Deployment:
Решение готово к интеграции в CI/CD. Docker-конфигурация позволяет запускать сервисы как в локальной среде разработки, так и в кластерах k3s.
